# ai-lawyer: налоговый second opinion для селлеров маркетплейсов

Сервис перепроверяет работу бухгалтера у **селлеров WB, Ozon и Яндекс Маркета на УСН (ИП и ООО)**:
берёт декларацию по УСН и КУДиР, находит ошибки и штрафные риски до подачи и пишет, какие вопросы
задать специалисту. Юрисдикция: РФ. Это second opinion, а не замена бухгалтера.

Идея двухконтурная:

```
ИССЛЕДОВАНИЕ (раз в месяц / при изменении права)      ПРОВЕРКА (на каждого клиента)
12 зон → 12 исследователей (параллельно)              документы клиента → интейк (вопросы)
   → верификатор «исходно не верю» на каждую зону        → извлечение чисел (LLM переписывает)
   → 3 критика полноты (календарь/форензик/проверки)    → детерминированные сверки (считает код)
   → дозакрытие пробелов                                → судья (только на доверенной базе знаний)
   → knowledge/<run>/  (версионируется в git)           → отчёт: таблица находок + вопросы бухгалтеру
```

## Статус (честно)

| Что | Состояние |
|---|---|
| Пайплайны research и review, правило доверия, детерминированные проверки | Работают, 122 теста, покрытие 97% |
| Адаптеры Yandex AI Studio, Yandex Search API, GigaChat | Формат запросов и ответов проверен **на фикстурах по документации**. На живом API **не прогонялись**. GigaChat экспериментальный |
| Содержание: 12 зон, чек-лист, `rules/usn.yaml` | Черновик. Правила помечены `verified: false`. **Не проверялось практикующим налоговым консультантом** |
| Извлечение чисел из реальных PDF/XLSX из 1С, Контур, Моё дело | Не проверялось, ждёт реальных документов |
| Сверка с отчётами маркетплейсов | Не реализована (см. `docs/ROADMAP.md`) |

Первое действие после получения ключей: `python -m lawyer doctor`. Он за минуту покажет, работает ли
у выбранной модели tool calling и отдаёт ли результаты поиск.

## Быстрый старт

```bash
uv venv && uv pip install -e ".[api,dev]"
cp .env.example .env            # впиши ключи; без них работает только режим --mock
python -m lawyer --mock review cases/demo       # прогон без ключей и сети
```

С реальными ключами:

```bash
python -m lawyer doctor                          # ключи, tool calling, поиск, fetch
python -m lawyer zones                           # 12 зон исследования
python -m lawyer research --tax-year 2026 --zones usn-income-recognition-marketplaces
python -m lawyer research --tax-year 2026        # все зоны → knowledge/<run>/
python -m lawyer review cases/<клиент>           # проверка документов
```

Режим `--mock` пишет в `out/mock-knowledge/`, а не в `knowledge/`: фейковые «доверенные»
утверждения не должны попасть в настоящую базу.

## Структура

```
prompts/            промпты агентов (markdown, роль задаёт маркер <!-- role: ... -->)
research/zones.yaml 12 зон исследования: вопросы, а не факты
rules/usn.yaml      числа и сроки для проверок; verified:false до подтверждения research
skills/             чек-лист (общий для ядра и Claude Code) и тонкая обёртка-скилл
knowledge/          результат research: версионируется, читается review
cases/<клиент>/     profile.yaml, context.md, docs/ (реальные docs не коммитятся)
src/lawyer/
  llm/              LLMProvider: yandex, gigachat, mock; общий лимит параллелизма
  tools/            web_search (Yandex Search API), fetch_url, белый список источников по весу
  agent.py          цикл «модель ↔ инструменты»
  research/         зоны, исследователь, верификатор, критики, оркестратор, база знаний
  review/           приёмка, извлечение, checks.py (детерминированные), судья, отчёт
  cli.py  api.py    тонкие обёртки: CLI и FastAPI-заглушка
tests/              122 теста без сети и ключей
```

## Три правила, на которых всё держится

1. **Доверие определяет код, а не промпт.** В базу знаний как «доверенное» попадает только то, что
   подтвердил независимый верификатор и что опирается на первоисточник (ФНС, Минфин, pravo.gov.ru,
   суды, КонсультантПлюс/Гарант, оферты площадок). Блог и мнение агента не попадают никогда.
2. **Цифры считает код.** LLM только переписывает числа из документов; арифметику, сверку КУДиР с
   декларацией, срок подачи и предел вычета взносов проверяют чистые функции в `review/checks.py`.
3. **Нет данных или правила — честное «не могу проверить»**, а не молчаливое «всё хорошо».

Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/SCOPE.md](docs/SCOPE.md),
[docs/ROADMAP.md](docs/ROADMAP.md).

## Как расширять

- **Новая зона исследования:** блок в `research/zones.yaml` (id, title, question, must_cover).
  Значения с `: ` внутри списков берите в кавычки.
- **Новая проверка:** функция в `review/checks.py` + строка в `run_checks` + тест. Нужное число — в
  `rules/usn.yaml`; нет значения — проверка обязана вернуть «нужен research».
- **Новый провайдер LLM:** подкласс `OpenAICompatProvider` (если API совместим) или реализация
  `LLMProvider` из `llm/base.py` + ветка в `llm/factory.py`.
