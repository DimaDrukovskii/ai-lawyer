# Налоговый second opinion для селлера маркетплейса (УСН, РФ)

Это **тонкая обёртка** над Python-ядром репозитория. Вся логика живёт в `src/lawyer/`, чек-лист — в
`checklist.md` рядом. Скилл не дублирует их, а запускает.

## Порядок работы

1. **Кейс.** Папка `cases/<имя>/` с `profile.yaml` (ИП/ООО, объект УСН, регион, год, сотрудники,
   площадки, НДС), `context.md` и `docs/` (декларация, КУДиР: PDF, XLSX, CSV, TXT, XML).
   Не хватает профиля — спроси у пользователя, не выдумывай.
2. **База знаний.** Проверь `knowledge/LATEST`. Нет или старше нескольких недель, либо сменился
   налоговый год — предложи `python -m lawyer research --tax-year <год>` (долго и платно: скажи об этом).
3. **Проверка.** `python -m lawyer review cases/<имя>`. Для пробного прогона без ключей:
   `python -m lawyer --mock review cases/demo`.
4. **Отчёт.** Читай `out/review/<имя>_report.md`. Перескажи пользователю: главный риск, цену ошибки,
   вопросы бухгалтеру. Находки с пометкой `⚠ проверить у специалиста` не выдавай за установленный факт.

## Жёсткие правила

- Числа и нормы права — только из базы знаний (`knowledge/<run>/zones/*.md`), с источником и датой.
  Нет в базе — «не подтверждено», а не ответ по памяти.
- Источник уровня «блог» — только наводка. Число из блога не принимай.
- Не заменяй бухгалтера: итог — список рисков и вопросов к специалисту.
- Реальные документы клиента (ИНН, ФИО, счета) не коммить и не отправляй никуда, кроме настроенного
  провайдера LLM.
